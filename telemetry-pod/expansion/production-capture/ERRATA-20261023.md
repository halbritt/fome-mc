## Why an erratum, not an edit

- **No generator and no consumer.** `production-capture/SHA256SUMS` has no generator in the repository, and
  no check reads it: `git grep SHA256SUMS` finds none for this file.
- **The managed manifest is a different file.** The `SHA256SUMS` that tooling writes and checks is the
  retained emission's (`retain.py:124-125` writes and `retain.py:212-217` checks
  `evidence/emission-7d5b0d4d/SHA256SUMS`); `README.md:136` describes that one.
- **No documented rule for mutable docs.** This manifest has none. It was regenerated by hand-run recipe in
  each delivery commit (`find . -type f ! -name SHA256SUMS | LC_ALL=C sort | xargs sha256sum`), which is
  practice, not design.
- **So it is treated as a seal.** `README.md` is not edited.
- **This erratum is deliberately not added to `SHA256SUMS`.** The manifest has no rule requiring it.
  `sha256sum -c SHA256SUMS` checks only the listed files, so it still exits 0. The hand recipe would now
  list one extra file.
