# Production capture for the Rev-3 microSD pod (AGENTEE-207/197)

This directory captures the electrical and mechanical inputs a production pod run needs, for the
current microSD source (`../storage-microsd/`, 305 references). Phase B then runs the genuine
agent-ee producers on the capture and stops at the real `pod_driver` dry run. It is capture and
composition evidence. No placement, routing, campaign or model ran, and nothing is accepted.

**Status: one exact missing capture blocks the run.** J3 (Hirose DM3AT-SF-PEJM5, LCSC C114218)
has no datasheet. LCSC and Hirose serve the PDF behind HTML gates, and no copy exists offline.
agent-ee admits a named part only with a captured datasheet, so J3 cannot enter the parts
manifest. Without J3, binding-fill and the envelope content (J3 is a fixed footprint) refuse.
Every other input is captured, bound by hash and accepted by its owned validator.

## Decisions (autonomous, recorded per AGENTS.md; owner review after the fact)

- **J1 is hand-fitted (POD-AC-5).** AC-5 names the AMPSEAL header as hand-fitted after delivery,
  and J1 (TE 1-776163-1, C596198) has captured stock 0 and `assemblyComponentFlag` false. The
  deviation is `hand_soldered` / `owner_hand_fit`, so binding-fill marks J1 `JLCPCB_Assembly:
  not_assembled`. No other part qualifies: U3 (618) and J2 (191) were in stock at capture, so AC-5's
  "if unstocked" does not apply to them. Alternatives: leave J1 assembled, which needs a stocked
  source that does not exist in any capture, or substitute the tin 776163-1, which is a different
  part. Reverse by emptying `deviations` in `build.py`.
- **The bound projection starts as the current intent.** `binding_fill.configuration(output=…)` needs a
  captured output, so `composition/intent.bound.json` is seeded with the writer intent's exact
  bytes. The binding-fill step replaces it before emission. Nothing is stripped or recreated.
- **The fab profile stays `02e48472…`,** the profile the envelope already binds. agent-ee main's
  fixture has since moved to `00e3e2fc…` (AGENTEE-272 via tier). It was not switched silently.

## Phase B (`pipeline.py`), on a fresh copy of the capture

The results, with exact messages, are in the worker result. In order:

1. `binding_fill.configuration(output=intent.bound.json, source_migration=True)` is accepted.
   `fill` refuses: `part_ref coverage must equal all non-power components` (J3).
2. `scaffold.scaffold` (stage one) is accepted. `write_envelope_content` refuses: `fixed footprints are not
   declared parts instances: J3`.
3. The emitter/annotation (`schematic_stage`) and `add_planes` declarations are accepted. So are the
   routing preflight (pin 5f1c072) and `validate_plan`.
4. The derived policy passes `refuse_policy_sources`. On the efafaef scope it names H1–H4 outside the
   placement subject (scope-b fixes this). Neither scope maps a placement check with `params.envelope`,
   so the adapter would pass the packer no envelope overhangs. The 18 iter8n block candidates bind
   `a8b2585e…` and need repacking with the released AGENTEE-439 engine, which is not on agent-ee origin/main.
5. `pod_driver.build(dry_run)`: on efafaef it refuses on the policy (H1–H4); on scope-b it passes
   `validate_configuration` and the receipted scaffold, then the receipted envelope-content step
   fails on J3.

Diagnostics run on scratch copies only and are never inputs:

- **Binding-fill on an intent copy without J3.** It shows the existing `Qualification` (174),
  `AGENT_EE_Ratings` (98), `Voltage` (55) and `Power` (43) fields have no captured producer.
  With those set aside, all 304 other bindings revalidate. J1 gains `JLCPCB_Assembly` and the six
  probe markers migrate.
- **Envelope content without J3.** U1's retention is verified natively, and both D-PCB rule areas
  are identical to the corrected-policy board `ca2.kicad_pcb`.
- **J3's transform.** The courtyard overhangs the left edge by 20.145 mm (declared 20.3), and its pads
  equal the iter8n seed's.

## Reproduce

```sh
/usr/bin/python3 telemetry-pod/expansion/production-capture/build.py AGENT_EE_EXPORT --check
/usr/bin/python3 telemetry-pod/expansion/production-capture/build.py AGENT_EE_EXPORT --out /new/capture
AGENT_EE_TOOL_SOURCE_CACHE=/abs/cache /usr/bin/python3 telemetry-pod/expansion/production-capture/pipeline.py \
  AGENT_EE_EXPORT ROUTER_CHECKOUT COMPILED_SCOPE_DIR /new/capture /new/pipeline-out
```

`AGENT_EE_EXPORT` is `git archive` of agent-ee origin/main (`014b3498…` here). `COMPILED_SCOPE_DIR` is
the compiled Rev-3 scope (`requirements/rev3-microsd/compiled/` from 197's efafaef or scope-b ebb1fa1,
neither on main yet). The build exports the microSD netlist on a temporary copy; no design file is
re-saved.
