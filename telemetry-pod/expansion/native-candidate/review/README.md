# Independent expanded native candidate review

No source-to-native component or electrical-net mismatch found. `check_native.py CANDIDATE_DIR THERMISTOR_INPUTS REPORT_JSON` passes 4,776 checks with `PYTHONPATH` pointing to agent-ee/src. It imports only the bounded S-expression parser; it does not import emitter or preparation helpers. The candidate directory contains inputs/, project/, and native.xml, matching the producer's fresh-run layout.

All 332 source components are present in the parsed native schematic with expected units, values, footprints, on-board and BOM attributes. Native XML includes 326 components; its omission of the six power-flag symbols is expected. All 193 named native nets exactly match source terminal sets after removal of those flag terminals. All 175 declared NC terminals are singleton native nets marked no_connect, and the schematic has 175 explicit NC markers. Native XML graph checks do not establish power-flag wire geometry independently of the native exporter.

The only preparation deltas from frozen thermistor inputs are in_bom=false on JP1–JP5, the exact shortened auxiliary sheet title, the added captured C128 1206 footprint, and the single ADC pin-type correction with its library hash. All earlier capture bytes are preserved except the independently checked MCP3208 DOUT electrical-type correction described below. Copper jumpers remain on-board, retain both electrical terminals and remain in the native netlist. Direct inspection of native-bom.csv found exactly 315 references: the source set minus JP1–JP5, existing TP1–TP6 PogoPads, and six power flags. This is source/BOM policy evidence, not fabrication acceptance or component-binding approval.

The retained disconnected-pin negative control removes U20 SDO physical pin12 from the native shared SPI net. The checker fails on exact net membership, with evidence in negative-probes.json. No source circuit was changed for this probe.

The prior ERC warning came from U20 SDO tri-state connected to U4 DOUT output. The captured Microchip DS21298E figures 1-2/1-3 and 5-1/5-2 explicitly show deselected DOUT high impedance. Changing physical pin12 from output to tri_state faithfully models that behavior. The checker parses the complete old and new captured library, locates pin12 by number and Dout name, and compares the full trees after changing that single electrical-type atom. All pin numbers, geometry, metadata and other pins remain unchanged; only the corresponding intent library hash changes. Native U4 pin12 must also be tri_state. Both disconnected U20 pin12 and reverting the ADC source pin type are rejected. Native ERC now has zero findings; no exclusion or waiver was added. This clears the inaccurate symbol-type warning, not shared-bus operational qualification.

Shared SPI contract remains open:

- MCP3208 DS21298E electrical table specifies tDIS=100ns under default VDD=5V, VREF=5V, -40..85C conditions. Do not promote this to a guaranteed 3.3V turnaround time. Its documented modes0,0 and1,1 correspond to SPI modes0 and3. Initial1MHz does not by itself establish full timing margin.
- Captured MCP2518FD DS20006027B table7-6 parameter10 specifies up to2 TSCK from nCS rising to SDO high impedance at50pF, VDD2.7..5.5V and applicable E/H temperature range. At proposed1MHz this is2us. Its nCS setup/hold, FSCK<=0.85*(FSYSCLK/2), and source clock conditions remain applicable. This is elapsed-time specification, not proof that firmware supplies adequate turnaround.
- Captured ST LSM6DSO32 DocID032891 Rev1 section4.4.1/table6 gives50ns SDO disable, mode3, general Vdd/Top conditions; the footnote says characterized at10MHz, not tested in production. Section5 supports modes0/3. CS high also enables I2C by default; CTRL4_C I2C_disable, interface configuration and reset/startup behavior need deliberate review before relying on SPI-only arbitration.
- Chip selects must exclude simultaneous drive during startup, reset, mode switching and normal transfers. Shared-line capacitance, actual edges and firmware timing have not been qualified. MCP2518FD DS80000789C errata still require applicable CRC retry/error handling, address-boundary handling, clock constraints and single-byte IOCON writes for LAT0 silent-gate control. A symbol correction implements none of these behaviors.

Prior precision, leakage/backfeed, transient, cold-start, capacitor effectiveness/stability, thermal, component-binding, assembly availability, mechanical, placement/routing and hardware qualification holds remain. This review establishes candidate source preservation and native graph correspondence only.
